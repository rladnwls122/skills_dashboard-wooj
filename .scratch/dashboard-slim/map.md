# 대회 투입용 대시보드 슬림화

Labels: `wayfinder:map`

## Destination

대회 당일 트래픽 2시간 동안 **`성능` 탭 하나만 띄워놓고 상시 감시가 되는 대시보드**로 개조를 마친 상태.
구체적으로는 (1) `성능` 탭 한 장에서 5초 안에 이상 유무 판단, (2) 비정상 요청을 추천 → COUNT 실측 → BLOCK 승격
흐름으로 사람이 눌러 차단, (3) 채점 창 기준 노드 대수 지표를 화면이 정확히 제시 — 이 셋이 실제로 동작하는 코드로
들어가 있으면 도착이다.

  - `성능` — 2시간 동안 띄워두는 화면. 5초 판단.
  - `트래픽` — 지금 뭐가 들어오고 있나 (로그, 차단 통계, 이상 패턴).
  - `규칙 생성` — 그래서 뭘 막나 (추천 → COUNT → 승격 → 롤백, 한 규칙의 일생).
- **설정은 탭이 아니라 톱니 모달**(확정). 값은 자동 탐색이 기본이고, 설정은 그게 틀렸을 때
  사람이 강제로 덮어쓰는 안전장치다 — 평소엔 보일 이유가 없다.

## Decisions so far

<!-- 닫힌 티켓 한 줄씩 -->

- [채점 창 전체의 노드 대수를 사후 재구성할 수 있는가](issues/02-node-count-history.md) — **가능**.
  대시보드가 꺼져 있어도 CloudTrail `RunInstances`/`TerminateInstances`(사전 설정 불필요, 90일 보존,
  커버리지 100%)로 재구성된다. **ASG 그룹 메트릭은 쓰면 안 된다** — Karpenter 노드가 어떤 ASG에도
  속하지 않아 채점 대상을 통째로 놓친다. 자체 SQLite 적재는 정확도가 아니라 실시간 표시용.
- [앱 로그와 WAF 로그를 requestid로 조인할 수 있는가](issues/07-log-join.md) — **GET만 가능**.
  앱이 `requestid`/`uuid`를 JSON 필드로 남기지만 **쿼리스트링에서만** 읽으므로 POST/PUT은 양쪽 다 값이 없다.
  WAF 로그가 us-east-1(CLOUDFRONT 스코프), 앱 로그가 ap-northeast-2라 **Insights 한 쿼리로는 못 한다** —
  COUNT 매칭 요청만 뽑아 `requestid` 목록으로 두 번째 쿼리를 던지고 **대시보드 코드에서 병합**한다.
  COUNT 판정은 `action`이 아니라 `nonTerminatingMatchingRules`에 있다. 2시간 대회 전체 스캔 비용 약 $1.2.
- [현재 화면 전수 인벤토리](issues/01-panel-inventory.md) — **75개 지표 / 36장 카드**, 삭제 제안 22행,
  죽은 코드 약 191KB(`src/`+`scripts/`의 1/3). 중복 1위는 **WAF 차단 건수가 4곳에 서로 다른 출처로** 있는 것.
  중요한 정정 둘: `ActionTab.tsx`는 살아 있고(`PerformanceTab.tsx:559`), **WAF 규칙 적용·롤백 기계는
  코드에 아예 없다**(`UpdateWebACLCommand`가 import만 되고 호출 0건) — `04`는 신규 구현이다.
- [3장에 무엇을 어떻게 배분하는가](issues/03-overview-layout.md) — **와이어프레임 확정**.
  `성능` 탭 above the fold = 채점 키 8줄 + 노드 대수 패널 → TRT/4XX/5XX/RDS 4타일
  → Node·Pod 개수 + 이상 목록. 그 아래는 문제가 있을 때 내려가는 영역이고 Deployment 조치는 맨 밑 고정.
  **상단 상태등 6칸(#69)은 통째로 없앤다** — 바로 아래 타일과 같은 값을 두 번 읽게 하고 있었다.
  이상 유무는 채점 키 8줄과 이상 목록(#13)이 직접 답한다. `buildSegments`도 같이 지운다.
  **드릴다운은 탭 이동으로 통일하고 카드 확대(`⤢`)는 폐기**, 컨텍스트는 시간창만 따라간다.
  `방화벽`·`로그`·`점검` 탭 폐기 — 단 프로브(#58·#59)는 `규칙 생성` 하단으로 옮겨 살린다.
  **신규 탭 파일은 0개** — `LogTab` → `TrafficTab` 이름 변경 1건, `PerformanceTab`·`AiTab` 편집,
  `OverviewTab`·`WafTab`·`CheckTab`·`IncidentTab` 삭제, `SettingsTab`은 모달 안으로 그대로 들어간다.
- [비정상 요청 대응 흐름](issues/04-block-flow.md) — **막는 건 UA와 SQLi 둘뿐**.
  경로 차단 규칙(#63)은 폐기한다 — 미지정 경로는 **ALB가 이미 404를 낸다**. 경로 통계는 감시용으로만 남는다.
  **단, 경로 스코프다운은 남는다**(WAF가 ALB 앞이라, UA/SQLi 규칙에 경로 AND가 없으면 미지정 경로가
  404 대신 403이 된다). 스코프다운은 경고가 아니라 **강제** — 없으면 조립도 업로드도 거부.
  **COUNT 단계는 SQLi에만 있다**: UA는 `추천됨 → BLOCK`(관측된 문자열이라 눈으로 이미 확인),
  SQLi는 `추천됨 → COUNT → BLOCK`(고정 시그니처라 우리 정상 쿼리가 걸릴지 모른다).
  상태는 로컬 테이블 없이 `GetWebACL`에서 매번 파생한다. 오탐 경보는 적용 시점 채점 키 스냅샷 대비
  5분 내 −1%p이며, 상태등이 없으므로 **규칙 행 + 이상 목록(#13)** 두 곳에 뜬다.
  1차 확인선은 정상 경로 프로브 — **UA는 COUNT를 안 거치므로 올린 직후 프로브 1회가 절차다.**
  신규 구현의 핵심은 `setRuleAction(rule, action|null)` **함수 하나** — 적용·승격·롤백이 전부 이것이다.
- [비용 패널](issues/05-cost-panel.md) — **최종 평균 대수 + 1대 증감 두 숫자**(누적 평균은 부제).
  실시간은 `describe-instances` 30초 폴링 단일 소스(규격 외 판정도 같은 응답으로 끝난다),
  최종 정산은 CloudTrail, **backfill은 기동 시 자동 1회**. 경기 시작 시각은 설정 모달에서 받고
  **미입력이면 잠정값을 만들지 않는다**. 패널에 색 판정·목표선·점수 표현을 두지 않는다.

결정은 `01`~`05`·`07`에서 다 섰다. 실행은 `06a`/`06b`/`06c` + `08`로 쪼갰고, main 세션과
wayfinder 세션이 같은 워크트리에서 **파일 단위로 나눠** 동시에 진행했다.
겹치는 파일은 `actions/dashboard.ts` 하나였고 서로 다른 위치에 붙여 충돌 없이 끝났다.

   COUNT 실측 병합 모듈(`wafcountevidence.ts`)만 wayfinder가 만들어 넘겼다.
3. [`06c` 비용 패널](issues/06c-cost-panel.md) — wayfinder. `nodecount.ts` + `NodeCostPanel`.
4. [`08` 운영 절차](issues/08-runbook.md) — wayfinder. `docs/RUNBOOK.md` 한 장.

### 나눠 일할 때 배운 것

- **읽기 전용 조사는 겹쳐도 되지만 편집은 파일 단위로 갈라야 한다.** 한쪽이 UI를 잡고 다른 쪽이
  신규 서버 모듈을 만드는 분할이 제일 잘 굴러갔다 — 신규 파일은 정의상 충돌하지 않는다.
- **중간 typecheck 실패를 남의 것으로 오해하지 말 것.** 상대가 편집 중인 파일의 에러는 내 문제가
  아니지만, 내 파일의 에러도 그 소음에 섞여 안 보인다. 파일별로 확인해야 한다.
- **테스트 파일이 마지막 충돌 지점이었다.** 양쪽이 같은 `ruleassemble.test.mjs`를 고치려 해서,
  한쪽이 손을 떼고 남은 실패 목록만 넘기는 쪽으로 정리했다.
