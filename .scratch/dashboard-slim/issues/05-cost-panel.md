# 05 — 비용 패널: 무엇을 보여주면 스케일 결정을 할 수 있는가

Type: grilling
Status: resolved
Blocked by: 02

## Question

기존 README는 `cost ratio`를 "관측 불가"로 표에서 뺐다. 그 전제는 틀렸다 — 채점기는 채점 창 동안
**N분마다 집계한 인스턴스 대수**를 입력으로 쓰고, 그 값은 우리도 셀 수 있다.
다만 대수에서 점수로 가는 계산식은 **비공개 절대식**이므로 점수는 만들지 않는다.

`02`의 조사 결과를 놓고 정한다:

1. **패널이 내놓는 숫자** — 후보:
   - 채점 창 시작부터 지금까지의 **누적 시간가중 평균 대수**
   - 지금 대수를 끝까지 유지했을 때의 **최종 평균 대수** (남은 시간 반영)
   - 지금 1대 늘리거나 줄였을 때 최종 평균이 얼마나 움직이는가 (**한계 효과**)
   - 규격 외 인스턴스 목록 (타입·리전·미사용)
   셋 다 필요한가, 아니면 하나면 되는가. 요약 탭에 올라가는 건 어느 것인가.
2. **채점 창을 어떻게 아는가** — 경기 시작 시각을 설정에서 입력받는 방식이면 충분한가.
   입력이 없을 때 패널은 무엇을 보여주는가(빈 값? 대시보드 기동 시각 기준 잠정값?).
3. **소스 선택** — `02`는 "사후 조회 가능"으로 닫혔고, CloudTrail이 커버리지 100%·사전 설정 불필요라
   최종 정산 소스로 확정됐다. 남은 결정은 실시간 표시를 무엇으로 하는가다: `describe-instances` 폴링,
   ContainerInsights `cluster_node_count`(add-on 있을 때만), 아니면 둘을 섞을지.
   그리고 **ASG 그룹 메트릭은 쓰지 않는다** — Karpenter 노드를 놓친다.
   대시보드가 꺼져 있던 구간은 CloudTrail로 backfill되므로 구멍 표시는 필요 없지만,
   backfill을 언제 돌릴지(기동 시 자동? 버튼?)는 정해야 한다.
4. **갱신 주기** — 이 값이 몇 초마다 갱신되어야 의미가 있는가. 노드 수는 분 단위로 움직인다.
5. **점수를 만들지 않는다는 원칙을 화면이 어떻게 지키는가** — 패널이 "이 정도면 괜찮다"는 인상을
   주지 않으면서 대수만 정확히 전달하려면 무엇을 적어야 하는가.

`/grilling`으로 진행한다.

## Answer

### 패널 전문

`성능` 탭 최상단, 채점 키 8줄 바로 아래(`03`).

```
채점 창 노드 대수                          T+1h 기준 73분 경과 / 47분 남음
  최종 평균   4.3 대      ← 지금 4대를 끝까지 유지했을 때
  1대 증감    ±0.4 대     ← 지금 늘리거나 줄이면 최종 평균이 움직이는 폭
  누적 평균   3.9 대
  ⚠ 규격 외 1대  i-0abc123  t3.large  ap-northeast-2
```

### 1. 숫자는 둘 — 최종 평균과 한계 효과

**`최종 평균`이 주(主)다.** 스케일 결정은 "지금 몇 대인가"가 아니라 "이 결정이 끝났을 때 평균을 어디에
데려다 놓는가"의 문제라, 결정에 직접 붙는 숫자는 이것 하나다.

**`1대 증감`이 부(副)다.** 남은 시간이 짧아질수록 같은 1대의 무게가 가벼워지므로, 이 값 자체가
"지금 늘려도 되는가"의 답이다. 창 끝 10분에 `±0.08대`가 뜨면 망설일 이유가 없다는 뜻이다.

`누적 평균`은 최종 평균 계산의 중간값이라 작게 부제로만 둔다. 셋을 동등하게 크게 두면 5초 안에
어느 걸 볼지 매번 고르게 되고, 그건 `03`이 없애려는 문제 그 자체다.

계산은 시간가중이다. 창 길이 `W`(120분), 경과 `e`, 지금까지의 시간가중 평균 `A`, 현재 대수 `n`일 때

```
최종 평균 = (A × e + n × (W − e)) / W
1대 증감  = (W − e) / W
```

**`규격 외 인스턴스`는 0이 아닐 때만 나타난다.** 상시 표시하면 `0대`라는 글자가 공간만 먹는다.
판정은 `t3.medium`이 아니거나, `ap-northeast-2`가 아니거나, 어떤 노드로도 클러스터에 붙어 있지 않은
인스턴스다. 세 조건 다 `describe-instances` 응답 하나로 판정된다.

### 2. 채점 창 — 설정 모달에서 경기 시작 시각을 받는다. 없으면 만들지 않는다

- 톱니 모달에 `경기 시작 시각` 한 줄을 추가한다(`03`의 설정 모달). 채점 창은 `T+1h ~ T+3h`로 고정
  파생이라 따로 입력받지 않는다.
- **입력이 없으면 평균 자리에 숫자를 만들지 않는다.** `— 경기 시작 시각 미설정`을 적고, 현재 대수와
  규격 외 목록만 보여준다. 대시보드 기동 시각 기준 잠정값은 채택하지 않았다 — 창 시작이 틀리면
  시간가중 평균이 통째로 틀리고, 화면은 그게 틀렸다는 걸 표시할 방법이 없다.
  **틀린 숫자가 빈칸보다 나쁘다.**
- 시각을 나중에 입력해도 CloudTrail backfill(3)이 창 전 구간을 채우므로 손해가 없다. 그래서 잠정값을
  만들 이유가 더더욱 없다.

### 3. 소스 — `describe-instances` 폴링 단일 + 기동 시 CloudTrail backfill 자동

- **실시간 표시: `describe-instances` 30초 폴링.** ContainerInsights `cluster_node_count`는
  1분 해상도로 더 곱지만 `amazon-cloudwatch-observability` add-on이 창 시작 전에 깔려 있어야 하고,
  깔려 있어도 **규격 외 판정(타입·리전·미사용)에는 `describe-instances`가 어차피 필요하다.**
  두 소스를 섞으면 코드 경로가 둘이 되면서 얻는 게 해상도 30초뿐이라 남는 장사가 아니다.
  서버사이드 `--filters`를 걸어 페이지 버킷을 아끼고, 결과를 SQLite `metric_samples`에 적재한다.
- **최종 정산: CloudTrail `RunInstances`/`TerminateInstances`**(`02` 확정). 커버리지 100%,
  사전 설정 불필요, 90일 보존.
- **backfill은 대시보드 기동 시 자동 1회.** 버튼을 두지 않는다 — 사람이 눌러야 정확해지는 화면은
  안 누른 동안 조용히 틀린 값을 보여준다. `LookupEvents` 2 TPS 제약이 있지만 2시간치 이벤트는
  수십 건 규모라 문제되지 않는다. 화면이 빠진 구간을 표시할 필요도 없다(기동 즉시 메워지므로).
- **`AWS/AutoScaling` 그룹 메트릭은 쓰지 않는다.** Karpenter 노드가 어떤 ASG에도 속하지 않아
  채점 대상을 통째로 놓친다(`02`).

### 4. 갱신 주기 — 30초

노드는 분 단위로 움직이므로 30초면 충분히 앞선다. `describe-instances`는 Insights 스캔 비용이 없어
`03`이 걱정하는 비용/주기 충돌에 걸리지 않는다 — 즉 이 패널의 주기는 WindowBar의 전역 갱신 주기와
**따로 논다**. WindowBar를 60m/1m로 고정해도 이 패널만 30초로 돈다.

### 5. 점수를 만들지 않는다는 원칙을 지키는 방법

- **패널에 색으로 된 판정이 없다.** 초록/노랑/빨강 배지도, `양호`/`주의` 같은 낱말도, 목표선도 없다.
  숫자는 전부 회색·검정이다. 유일한 빨강은 `규격 외 인스턴스`인데, 그건 추정이 아니라
  **사실 판정**이다 — 과제가 허용한 목록 밖이라는 건 계산이 아니라 대조의 결과다.
- **이상 목록(#13)에 대수 관련 항목을 만들지 않는다.** 이상 목록은 "지금 사고인가"에 답하는 자리이고,
  대수에는 사고라고 부를 임계값이 없다. (`03`이 상단 상태등 6칸을 없앴으므로 거기 칸을 만들지
  않는다는 조항도 자연히 없어졌다.)
- 패널 하단에 한 줄을 고정한다:
  `채점식은 비공개다. 이 패널은 채점기 입력값(대수)만 세고 점수를 만들지 않는다.`
- `ESTIMATED SCORE`류 표현을 어떤 형태로도 쓰지 않는다. 진짜 값은 채점 플랫폼 화면에 이미 있다.
