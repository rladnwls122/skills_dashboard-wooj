## Question

`docs/RUNBOOK.md`를 쓴다. **맨 마지막에 한다** — 화면이 확정되기 전에 쓰면 두 번 고친다.
README에서 한 줄로 링크한다.

이 저장소 밖의 결정(노드 수, HPA 설정 같은 인프라 구성)은 적지 않는다. **우리 화면을 보고
우리가 무엇을 누르는지**만 적는다.

담을 것:

- **대회 전 준비** — 경기 시작 시각 입력, 로그 그룹·리소스 이름 자동 탐색 확인,
  SQLi 규칙 미리 조립해 두기(관측 없이 만들 수 있는 유일한 규칙).
- **T+1h, 트래픽 시작** — `성능` 탭을 띄운다. 무엇이 어느 값을 넘으면 무엇을 하는지
  (`03`의 판단선 표를 그대로 가져온다).
- **비정상 요청이 보일 때** — `트래픽` 탭 UA 목록 → `규칙 생성`에서 조립 → UA는 바로 BLOCK,
  SQLi는 COUNT 먼저. 올린 직후 프로브 1회. 오탐이면 `내리기`.
- **미지정 경로 404가 안 나올 때** — 원인은 WAF가 아니라 ALB/게이트웨이다(`04`의 5).
  WAF 규칙을 뒤지지 말 것.
- **노드를 늘릴지 판단할 때** — `1대 증감` 값을 보고 결정한다. 창 끝으로 갈수록 가벼워진다.
- **하면 안 되는 것** — IP 기반 차단(채점 부하생성기가 단일 IP), 경로 차단 규칙(ALB가 404를 낸다),
  스코프다운 없는 규칙.

한 장을 넘기지 않는다. 대회 중에 읽을 문서라 길면 안 읽는다.

## Answer

[`docs/RUNBOOK.md`](../../../docs/RUNBOOK.md) 작성 완료. README 최상단에서 한 줄로 링크한다
("대회 당일에 읽을 문서는 이게 아니라 RUNBOOK이다").

6절 구성이고 한 장을 넘지 않는다:

0. 경기 전 — 경기 시작 시각 입력, 자동 탐색, SQLi 규칙 미리 조립
1. 트래픽 시작 — 판단선 표 10행 ("이 값이 X를 넘으면 Y를 한다")
2. 비정상 요청이 보일 때 — UA는 바로 BLOCK 후 프로브 1회, SQLi는 COUNT 후 3분해 확인
3. 미지정 경로가 404로 안 끝날 때 — **WAF를 뒤지지 마라**, ALB/게이트웨이다
4. 노드 스케일 — `1대 증감`을 보고 결정, 규격 외는 즉시 처리
5. 하면 안 되는 것 — IP 차단, 경로 규칙, 스코프다운 없는 규칙, 자동 차단, 점수 계산
6. 값이 안 보일 때 — 증상별 확인 위치 6행

인프라 구성 결정은 적지 않았다(map의 Out of scope).
