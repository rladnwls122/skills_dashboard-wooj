# 대회 당일 운영 절차

경기 중에 읽는 문서다. 무엇을 보고 무엇을 누르는지만 적는다.
인프라 구성(노드 수, HPA, 캐시, EKS 튜닝)은 여기 없다 — 당일 상황에 달렸고 이 저장소는 대시보드만 다룬다.

용어는 [`CONTEXT.md`](../CONTEXT.md)를 따른다. 특히 **비정상 요청(403)** 과 **미지정 경로(404)** 는
서로 다른 기계가 처리한다.

---

## 0. 경기 전 (T ~ T+1h, 구축 시간)

이 시간에 노드를 몇 대 띄웠든 비용 점수에는 들어가지 않는다. 대신 대시보드를 준비한다.

0. **아직 설치 전이면 두 줄로 끝낸다.** corepack 은 Node 에 들어 있으므로 따로 깔 것이 없다.

   ```bash
   corepack enable pnpm
   pnpm install --frozen-lockfile
   ```

   npm 이 편하면 `npm ci` 도 된다. 락파일을 둘 다 두는 이유가 이것이다.
   `--frozen-lockfile`(과 `npm ci`)은 락파일을 그대로 쓴다 — `package.json` 과 어긋나면 조용히
   다른 버전을 깔지 않고 **실패한다.** 당일에는 그게 맞다.

   **필요한 것은 Node.js 24 뿐이다. mise 도 Go 도 쓰지 않는다.**
   자세한 절차는 [README 의 구축 런북](../README.md#구축-런북).

1. `pnpm dev` — `127.0.0.1:3100`. 원격 접근은 만들지 않는다. 채점 창 동안에는 이 탭을 앞에 둔다.
2. **톱니 → `AWS 자격증명` → `aws CLI 세션 불러오기`.** 로컬에 로그인된 세션(임시 키 + session
   token)을 그대로 가져온다. `연결 확인`이 계정 번호를 찍으면 끝이다.
   - 모든 패널이 한꺼번에 비면 대부분 여기다. 만료가 가까워지면 자동으로 다시 읽으므로
     경기 중에 다시 누를 일은 없다. 세션 자체가 죽었으면 `aws sso login` 후 한 번 더 누른다.
   - CLI가 없는 컴퓨터면 `키 직접 입력`에 통째로 붙여넣는다(`export …` 블록·`.env`·CLI JSON 모두 인식).
   - 리전·리소스 이름을 미리 정해 뒀다면 `cp .env.example .env` 로 적어 실행 파일 옆에 두면 기동할 때 바로 들어간다. 빈 값은 무시되고, 이미 export 된 환경변수가 파일보다 우선한다. 기동 로그의 `env <경로>` 줄로 확인.
   - 임시 키(ASIA…)는 **session token까지 세 값**을 같이 넣어야 한다.
3. **톱니 → 경기 시작 시각을 입력한다.** 이걸 안 넣으면 비용 패널이 평균을 만들지 않는다.
   `09:00` 처럼 시각만 넣으면 오늘로 읽는다.
4. 톱니의 나머지 10행이 비어 있거나 틀렸으면 **자동 탐색** 버튼을 누른다.
   패널이 비어 보이는 원인은 거의 항상 여기다.
5. `성능` 탭에 값이 실제로 들어오는지 확인한다. `관측 요청 0건`이면 로그 그룹이 틀렸거나
   트래픽이 아직 없는 것이다.
6. **`UA` 탭에서 패턴 세트 2개를 미리 만들어 둔다.** 경로 세트는 관측과 무관하게 지금 뽑을 수 있다.
   UA 세트는 트래픽이 있어야 채워지지만, AWS에 세트를 만들고 ARN을 받아 두는 일은 지금 해 두면
   경기 중에 규칙 JSON을 붙여넣기만 하면 된다. 규칙을 올리지는 않는다.

## 1. 트래픽 시작 (T+1h) — `성능` 탭을 띄워 놓는다

채점 창은 **T+1h ~ T+3h** 2시간이다. 이 창 안의 값만 채점에 들어간다.

화면 맨 위 두 줄이 채점기 입력값이다. 아래 표대로 움직인다.

키 이름은 채점기 로그(`results_<비번호>.log`)와 **같은 이름**을 쓴다. 나란히 놓고 읽으라고 그렇게 맞췄다.
각 줄에 지금 어느 채점 구간인지와 다음 구간까지 몇 %p 남았는지가 함께 나온다 — **그 %p 가 곧 다음 0.5점이다.**

| 보는 값 | 선 | 넘으면 하는 일 |
|---|---|---|
| (user/product/stress) availability | 90% | 그 API의 Pod / replica를 먼저 본다 (2xx·5초 이내 비율) |
| (…) performance ≤ 0.2s / ≤ 1.0s | availability는 높은데 이것만 낮음 | 스케일이 아니라 지연 문제 — 캐시·인덱스·limit |
| image download | 90% | `/images/` 정적 전송. S3·CloudFront·캐시를 본다. API Pod 문제가 아니다 |
| Exception Handling | 90% | 비정상 요청이 403으로, 미지정 경로가 404로 끝나는 비율. 2절·3절로 |
| TargetResponseTime | 0.5s | Pod·노드 CPU 확인. 2.0s + 200%면 즉시 스케일업 |
| Target 4XX | 50/min | `트래픽` 탭에서 404인지 403인지 가른다 |
| Target 5XX | 20/min | 앱 장애. 로그 → Pod 상태 → replica 순 |
| RDS Client Conn | 80 + TRT 동반 상승 | DB 병목이다. Pod를 늘려도 안 낫는다 |
| Node / Pod 현재 = max | — | 상한이 병목이다. max를 올린다 |
| 이상 목록 | CRITICAL 1건 | 근거를 펼쳐 읽는다. **이 카드가 유일한 경보다** |

채점 키 8줄은 5분마다 자동 갱신된다. 급하면 `⟳`.
채점 플랫폼의 `ESTIMATED SCORE`가 진짜 점수다 — 우리 화면은 점수를 만들지 않는다.

## 2. 비정상 요청이 보일 때

`트래픽` 탭 → UA 목록에서 스캐너·정찰 툴 User-Agent를 찾는다.
경로 통계는 감시용이다. 여기서 규칙을 만들지 않는다(3절 참조).

`UA` 탭에서 규칙은 하나다. **서비스 경로 AND 스캐너 UA** 일 때만 차단한다 —
UA만으로 막으면 미지정 경로에도 403이 나가고, 그건 3절이 말하는 위반이다.

**① `규칙 조립`** — 패턴 세트가 **2개** 나온다(경로용·UA용). 근거 목록에서 무엇이 패턴이 됐는지 먼저 읽는다.
정상 브라우저·`Go-http-client`·헬스체크는 애초에 패턴이 되지 않는다. 하나라도 보이면 조립하지 말고 멈춘다.

**② 패턴 세트 2개를 AWS에 먼저 만든다.** `생성 CLI 복사` 또는 콘솔.
받은 ARN 2개를 입력란에 넣으면 규칙 JSON의 자리표시자가 채워진다.
**자리표시자가 남은 채로 붙여넣으면 AWS가 거부한다** — 화면이 노란 줄로 경고한다.

**③ `COUNT로 올리기`** — 차단 없이 매칭만 시킨다. 바로 BLOCK 으로 가지 않는다.

**④ `COUNT 실측 조회`** — `매칭 n건 (정상 a · 비정상 b · 조인 불가 c)`.

- **정상이 1건이라도 있으면 승격하지 않는다.** 그만큼 403이 나간다.
- 조인 불가는 POST/PUT이라 판정할 수 없는 건이다. 비정상으로 세지 않는다.
- 매칭 20건 이상 + 정상 0건이면 `BLOCK으로 승격`.

**⑤ 승격 직후 하단 프로브를 한 번 돌린다.** 오탐을 즉시 알 수 있는 유일한 신호다.
정상 비율이 100%가 아니면 곧바로 `내리기`.

승격 후 5분 안에 `(api) availability` 가 1%p라도 떨어지면 오탐이다.
규칙 행이 빨개지고 이상 목록에 CRITICAL이 뜬다 → `내리기`.

> 시간이 없어 ③④를 건너뛰고 바로 BLOCK 으로 갈 수는 있다. 그럴 때는 ⑤를 **반드시** 한다.

> `WebACL "…" 을(를) 찾지 못했습니다 … 규칙 적용을 중단했습니다` 가 뜨면 이름이나 scope가 틀린 것이다.
> 다른 WebACL을 덮어쓰지 않으려고 일부러 멈춘 것이니, 톱니에서 이름을 고치고 다시 누른다.

## 3. 미지정 경로가 404로 안 끝날 때

`Exception Handling`은 두 가지를 한 비율로 묶는다 — 비정상 요청이 403으로 끝났는지, 그리고
미지정 경로가 404로 끝났는지. 낮다면 어느 쪽인지부터 가른다.

후자가 원인이면 **대개 WAF가 아니다.** (패널 주석이 "WAF가 미지정 경로를 막아 403이 된 n건"을
따로 세어 준다. 그 값이 0이 아니면 그건 WAF다 — 미지정 경로를 BLOCK 하는 규칙을 내린다.)

경로 차단 규칙을 아예 만들지 않고 모든 규칙에 경로 스코프다운을 강제하므로,
미지정 경로는 어떤 경우에도 WAF에 걸리지 않는다. ALB / 게이트웨이 설정을 본다.

## 4. 노드를 늘릴지 줄일지

비용 패널의 **`1대 증감`** 값을 보고 결정한다.

- 창 초반이면 1대가 최종 평균을 크게 움직인다. 신중하게.
- 창 끝 10분에 `±0.08대`면 망설일 이유가 없다. 필요하면 늘린다.
- `최종 평균`은 지금 대수를 끝까지 유지했을 때의 값이다. 현재 대수가 아니다.

**`규격 외` 빨간 줄이 뜨면 즉시 처리한다.** 허용 타입(`t3.medium` — 문제지 §7, `ALLOWED_INSTANCE_TYPE` 로 변경 가능)이 아니거나,
지정 리전 밖이거나, 클러스터에 붙어 있지 않은 인스턴스다. 존재 자체가 감점이다.

대시보드를 껐다 켜도 CloudTrail이 빈 구간을 메운다. 창 중간에 재시작해도 값은 맞는다.

---

## 5. 하면 안 되는 것

- **IP 기반 차단.** 채점 부하생성기가 단일 IP에서 때린다. 집중 IP는 정상이다.
  이걸 막으면 채점 트래픽을 막는 것이다.
- **경로 차단 규칙.** 미지정 경로는 ALB가 404를 낸다. WAF가 막으면 403이 나가 요구사항 위반이다.
- **스코프다운 없는 규칙.** 화면이 거부하지만, 콘솔에서 직접 만들지도 마라.
- **자동 차단.** WAF와 Deployment 변경은 항상 사람이 누른다.
- **점수 계산.** 채점식은 비공개 절대식이다. 근사치를 만들면 반드시 틀린다.

## 6. 값이 안 보일 때

| 증상 | 먼저 볼 곳 |
|---|---|
| **모든** 패널이 한꺼번에 비었다 | 톱니 → `AWS 자격증명`. 세션 만료가 가장 흔하다 |
| 패널 하나가 비었다 | 톱니 → 리소스 이름. 자동 탐색 |
| `관측 요청 0건` | 앱 로그 그룹 이름(EKS Container Insights 의 `/aws/containerinsights/<클러스터>/application`), 또는 트래픽이 아직 없음. 로그에 `[GIN]` 액세스 라인이 있어야 한다 — `docs/binaries.md` |
| 비용 패널이 `경기 시작 시각 미설정` | 톱니 → 경기 시작 시각 |
| WAF 샘플 0건 | 트래픽이 없다는 뜻이 아니다. 아무 규칙도 매칭하지 않은 것 |
| Pod 사용률이 `limit 없음` | manifest에 limit이 없다. 비율을 못 낸다 |
| 상단바 갱신 시각(K8S·CW·WAF) 한 줄이 멈춤 | 그 소스가 죽었다 |
| K8s만 `ENOTFOUND …eks.amazonaws.com` | kubeconfig가 옛 클러스터를 가리킨다 → `aws eks update-kubeconfig` 재실행 |
| `Exception Handling` 이 0 | `WAF_LOG_GROUP` 미설정. 앱 로그만으로는 차단 건수를 볼 수 없다 |
| 화면이 갱신을 멈춘 것 같다 | 다른 탭·창을 보고 있으면 폴링이 멈춘다(의도된 동작). 앞으로 가져오면 즉시 갱신된다. **채점 창 동안에는 앞에 둘 것** — 가려 두면 Pod·Node 사용률 이력에 구멍이 생긴다 |
| `…는 이미 사용 중입니다` | 이전 백엔드가 살아 있다. 종료하거나 `pnpm dev -p 3110` |

## 7. 경기 중 대시보드가 죽으면

당황할 것 없다. **읽기 도구다. 죽어도 채점에는 영향이 없다.**

```bash
pnpm dev            # 그대로 다시 띄운다
```

- 설정과 주입한 자격증명은 SQLite에 남아 있다(세션 한정 주입은 다시 불러와야 한다).
- 비용 패널의 꺼져 있던 구간은 CloudTrail로 자동으로 메워진다 — 창 중간에 재시작해도 평균은 맞는다.
- 포트가 잡혀 있다는 메시지가 나오면 이전 프로세스가 살아 있는 것이다. 종료하거나 `-p` 로 다른 포트를 쓴다.
