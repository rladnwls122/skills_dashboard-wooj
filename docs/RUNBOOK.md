# 대회 당일 운영 절차

경기 중에 읽는 문서다. 무엇을 보고 무엇을 누르는지만 적는다.
인프라 구성(노드 수, HPA, 캐시, EKS 튜닝)은 여기 없다 — 당일 상황에 달렸고 이 저장소는 대시보드만 다룬다.

용어는 [`CONTEXT.md`](../CONTEXT.md)를 따른다. 특히 **비정상 요청(403)** 과 **미지정 경로(404)** 는
서로 다른 기계가 처리한다.

---

## 0. 경기 전 (T ~ T+1h, 구축 시간)

이 시간에 노드를 몇 대 띄웠든 비용 점수에는 들어가지 않는다. 대신 대시보드를 준비한다.

1. `pnpm start` — `127.0.0.1:3100`. 원격 접근은 만들지 않는다.
2. **톱니 → 경기 시작 시각을 입력한다.** 이걸 안 넣으면 비용 패널이 평균을 만들지 않는다.
   `09:00` 처럼 시각만 넣으면 오늘로 읽는다.
3. 톱니의 나머지 10행이 비어 있거나 틀렸으면 **자동 탐색** 버튼을 누른다.
   패널이 비어 보이는 원인은 거의 항상 여기다.
4. `성능` 탭에 값이 실제로 들어오는지 확인한다. `관측 요청 0건`이면 로그 그룹이 틀렸거나
   트래픽이 아직 없는 것이다.
5. **SQLi 규칙을 미리 조립해 둔다.** 관측 없이 만들 수 있는 유일한 규칙이라 지금 뽑아 놓는다.
   올리지는 않는다.

---

## 1. 트래픽 시작 (T+1h) — `성능` 탭을 띄워 놓는다

채점 창은 **T+1h ~ T+3h** 2시간이다. 이 창 안의 값만 채점에 들어간다.

화면 맨 위 두 줄이 채점기 입력값이다. 아래 표대로 움직인다.

| 보는 값 | 선 | 넘으면 하는 일 |
|---|---|---|
| availability (user/product/stress) | 90% | 그 API의 Pod / replica를 먼저 본다 |
| performance | availability는 100%인데 이것만 낮음 | 스케일이 아니라 지연 문제 — 캐시·인덱스·limit |
| image download | 100% 미만 | 정적 자산 경로가 깨졌다 |
| Exception Handling | 100% 미만 | **WAF를 뒤지지 마라.** 3절로 |
| TargetResponseTime | 0.5s | Pod·노드 CPU 확인. 2.0s + 200%면 즉시 스케일업 |
| Target 4XX | 50/min | `트래픽` 탭에서 404인지 403인지 가른다 |
| Target 5XX | 20/min | 앱 장애. 로그 → Pod 상태 → replica 순 |
| RDS Client Conn | 80 + TRT 동반 상승 | DB 병목이다. Pod를 늘려도 안 낫는다 |
| Node / Pod 현재 = max | — | 상한이 병목이다. max를 올린다 |
| 이상 목록 | CRITICAL 1건 | 근거를 펼쳐 읽는다. **이 카드가 유일한 경보다** |

채점 키 8줄은 5분마다 자동 갱신된다. 급하면 `⟳`.
채점 플랫폼의 `ESTIMATED SCORE`가 진짜 점수다 — 우리 화면은 점수를 만들지 않는다.

---

## 2. 비정상 요청이 보일 때

`트래픽` 탭 → UA 목록에서 스캐너·정찰 툴 User-Agent를 찾는다.
경로 통계는 감시용이다. 여기서 규칙을 만들지 않는다(3절 참조).

`규칙 생성` 탭에서:

**UA 규칙** — `BLOCK으로 올리기`를 바로 누른다. 관측된 문자열에서 조립되므로 무엇을 막는지 이미 봤다.
**누른 직후 하단 프로브를 한 번 돌린다.** COUNT를 거치지 않으므로 이게 유일한 즉시 확인선이다.
정상 비율이 100%가 아니면 곧바로 `내리기`.

**SQLi 규칙** — `COUNT로 올리기` 먼저. 고정 시그니처라 우리 정상 쿼리가 걸릴지 모른다.
규칙 행을 펼치면 `매칭 n건 (정상 a · 비정상 b · 조인 불가 c)`가 나온다.

- **정상이 1건이라도 있으면 승격하지 않는다.** 그만큼 403이 나간다.
- 조인 불가는 POST/PUT이라 판정할 수 없는 건이다. 비정상으로 세지 않는다.
- 매칭 20건 이상 + 정상 0건이면 `BLOCK으로 승격`.

승격 후 5분 안에 채점 키 availability가 1%p라도 떨어지면 오탐이다.
규칙 행이 빨개지고 이상 목록에 CRITICAL이 뜬다 → `내리기`.

---

## 3. 미지정 경로가 404로 안 끝날 때

`Exception Handling`이 100% 미만이면 **원인은 WAF가 아니다.**

경로 차단 규칙을 아예 만들지 않고 모든 규칙에 경로 스코프다운을 강제하므로,
미지정 경로는 어떤 경우에도 WAF에 걸리지 않는다. ALB / 게이트웨이 설정을 본다.

---

## 4. 노드를 늘릴지 줄일지

비용 패널의 **`1대 증감`** 값을 보고 결정한다.

- 창 초반이면 1대가 최종 평균을 크게 움직인다. 신중하게.
- 창 끝 10분에 `±0.08대`면 망설일 이유가 없다. 필요하면 늘린다.
- `최종 평균`은 지금 대수를 끝까지 유지했을 때의 값이다. 현재 대수가 아니다.

**`규격 외` 빨간 줄이 뜨면 즉시 처리한다.** `t3.medium`이 아니거나, 지정 리전 밖이거나,
클러스터에 붙어 있지 않은 인스턴스다. 존재 자체가 감점이다.

대시보드를 껐다 켜도 CloudTrail이 빈 구간을 메운다. 창 중간에 재시작해도 값은 맞는다.

---

## 5. 하면 안 되는 것

- **IP 기반 차단.** 채점 부하생성기가 단일 IP에서 때린다. 집중 IP는 정상이다.
  이걸 막으면 채점 트래픽을 막는 것이다.
- **경로 차단 규칙.** 미지정 경로는 ALB가 404를 낸다. WAF가 막으면 403이 나가 요구사항 위반이다.
- **스코프다운 없는 규칙.** 화면이 거부하지만, 콘솔에서 직접 만들지도 마라.
- **자동 차단.** WAF와 Deployment 변경은 항상 사람이 누른다.
- **점수 계산.** 채점식은 비공개 절대식이다. 근사치를 만들면 반드시 틀린다.

---

## 6. 값이 안 보일 때

| 증상 | 먼저 볼 곳 |
|---|---|
| 패널이 통째로 비었다 | 톱니 → 리소스 이름. 자동 탐색 |
| `관측 요청 0건` | 앱 로그 그룹 이름, 또는 트래픽이 아직 없음 |
| 비용 패널이 `경기 시작 시각 미설정` | 톱니 → 경기 시작 시각 |
| WAF 샘플 0건 | 트래픽이 없다는 뜻이 아니다. 아무 규칙도 매칭하지 않은 것 |
| Pod 사용률이 `limit 없음` | manifest에 limit이 없다. 비율을 못 낸다 |
| 사이드바 갱신 시각 한 줄이 멈춤 | 그 소스가 죽었다 |
